# Решения по облачному бэкенду Maestro

Коротко: что решено и почему. Новые решения дописываются внизу.

## Решения владельца (2026-11-13)

1. **Никуда не пушим.** `origin` — чужой репозиторий Maestro. Все коммиты только локально,
   в ветку `rezhisser-2.0-full`; удалённой пары у неё нет и не будет.
2. **Настоящие ключи и платежи не ждём и не просим.** Проверка — на локальных заглушках API
   и настройках без секретов. Настоящие ключи — жёсткий блок, фиксируется в `STATUS.md`.
3. **Ветка помощника `rezhisser-2.0-helper` сливается** в `rezhisser-2.0-full` без удалений:
   `CLOUD_HOOKS.md`, `CLOUD_KEYS.md`, `tests/test_cloud_call_sites.py`.
4. Ничего не удалять из Maestro, интерфейс один в один; Factory, покупки, планировщик и
   автозапуск — не трогаем.

## Технические решения агента

- **Одна точка встраивания** — `launch._run_generation`, рядом с ComfyUI. Studio, Director и
  операции Editor идут через неё; отдельные крючки в `director_*` / `editor_*` не нужны
  (подтверждено в `CLOUD_HOOKS.md`).
- **Провайдер выбирается в `.env` (`CLOUD_PROVIDER`)** и фиксируется на задаче при старте;
  один переключатель виден в Studio, Director и Настройках.
- **Неподдерживаемые облаком режимы** (исходное видео, маски, аудио-гайд, Viggle,
  repaint/outpaint/recast, blend, звук, клипы > 15 с) получают явную ошибку
  «переключите на Local», а не тихую подмену.
- **Разрешение** H3: 768P (нативно) или 2K для кадров от 1080 px — 1080P API не принимают.
- **Окружение на этом ПК:** torch CPU + requirements без тяжёлых GPU-пакетов (на диске ~8 ГБ).
  Старт без CUDA обеспечен одной строкой в `wgp.py`.
- **Облачная LLM** берётся из `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL` только когда выбран облачный
  провайдер и в настройках LLM стоит Local; явный удалённый провайдер в настройках главнее.
- **Editor:** серверные `editor_*` не трогаем (генерацию не вызывают, `CLOUD_HOOKS.md`).
  В UI титров блок «установите модель» действует только при локальной генерации —
  в облаке веса не нужны.
- **Устойчивость UI:** если `/api/v1/cloud-config` недоступен или отвечает не тем, переключатель
  облака скрывается, а не роняет панель Studio/Director (нашёл UI-тест `sidebar_redesign`).
- **UI-тесты Maestro** запускаются Playwright из глобального пакета и Chrome; падения сверяются
  с чистым `main` во временной рабочей копии — чужие (уже существующие) падения не чиним.
- **Тест ComfyUI (`tests/test_comfyui_integration.py`)** считал любой `.execute(` в `_run_generation`
  и требовал ровно два. Тесты помощника требуют инлайн `return cloud_generation.execute(`.
  Файлы помощника не правим, поэтому тест Maestro уточнён: облачный вызов исключён из счёта,
  проверка двух вызовов ComfyUI сохранена. Ничего не удалено.
- **Полный прогон pytest** сверяется с чистым `main` по упавшим файлам. Падения, которые есть и на
  `main` (22), — существующие, не наши. Два теста (`flashvsr_plus_runtime`, `agent_access_desktop_bundle`)
  падают только в полном прогоне и проходят отдельно — нестабильность по времени.
- **ffmpeg:** на Windows Maestro скачивает «последний» ffmpeg (сейчас 9.0), а код рассчитан на опции,
  удалённые в 8.x. Код не меняем — кладём ffmpeg 7.1.1 в `app/ffmpeg_bins` (git-ignored); Maestro
  ставит эту папку первой в PATH. Это сняло 26 существующих падений и чинит экспорт Editor на этом ПК.
- **Тестовые записи задач** из галереи не удаляем: DELETE через API заблокирован правилами доступа.
- **Временную рабочую копию `main`** не удаляем автоматически: в ней junction на настоящие
  `ui/node_modules` и `ui/dist`, неосторожное удаление может их задеть.
- **Нестабильные тесты** (`agent_access_desktop_bundle`, `flashvsr_plus_runtime`) чиним в тестах, не в продукте:
  1 с на закрытие дочернего процесса в relay — поведение продукта; тест ждёт старта ребёнка. Импорт FlashVSR — лимит 300 с.
- **Помощник** влит обычным merge; правки после слияния — только чтобы интерфейс собирался (типы, линтер).
- **Запуск одной командой** — `start-rezhisser.cmd` / `stop-rezhisser.cmd`, без автозапуска и планировщика.
  Остановка трогает только python из `app\env` (и его дочерний процесс) на своём порту.
- **Wan 2.2 — основной видеодвижок fal** (открытая модель): `fal-ai/wan/v2.2-a14b/text-to-video` и `/image-to-video`.
  Turbo (`/image-to-video/turbo`) не по умолчанию: у него нет длины ролика; включается через `FAL_WAN_I2V_MODEL`.
  MiniMax H3 на fal — запасной: ролики длиннее 10 с (предел Wan 161 кадр при 16 к/с), только последний кадр,
  отказ Wan с HTTP 404/410/422 при отправке (ничего не сгенерировано). На 401/403 и сбои после отправки повтора нет —
  чтобы не платить дважды. fal пишет, что Wan 2.2 будет снят 2027-01-04 — тогда сработает этот запасной путь.
- **Выбор видеомодели не записывается из UI:** `.env*` закрыты для агента правилами доступа, а тест помощника требует
  описывать каждый записываемый ключ в `.env.example`. Поэтому Wan 2.2 — значение в коде, переопределение —
  переменная окружения `CLOUD_VIDEO_ENGINE=h3`. В интерфейсе fal подписан «Wan 2.2» и стоит первым облачным вариантом.
- **По умолчанию на этом ПК** выбран облачный fal (Wan 2.2) через штатную настройку приложения: GPU здесь нет.
- **Автопилот на сервере, а не в браузере:** длинная цепочка (минуты, десятки вызовов) идёт в потоке сервера со
  статусом по шагам; помощник запускает её одним инструментом `start_autopilot`, чат опрашивает статус. Так ролик
  не теряется, если закрыть панель. Готовые части Maestro: `cloud_generation.Fal` (очередь fal, Wan/H3, загрузка),
  поиск ffmpeg из `title_cards`, папка вывода галереи `wgp.save_path`, загрузки `/api/v1/upload`.
  Реестр инструментов фронтенда — тот же CopilotKit-подобный `useFrontendTool` из ветки помощника.
- **Склейка — свой короткий вызов ffmpeg:** `wgp.concatenate_multi_clip_videos` требует тяжёлый `wgp` и не приводит
  кадр к 1080x1920; нужен scale+pad под формат.
- **Порядок шагов:** прозрачный фон заливается белым до апскейла (апскейлер альфу не держит), JPEG доводит до 3840.
  Апскейл не больше 4x за вызов.
- **Повторы сцены:** 1 попытка + 2 повтора; первые две — Wan 2.2, последняя — MiniMax H3 (`fallback_engine` рецепта).
- **Входные файлы автопилота — только из `uploads/`** (`resolve_upload`): путь из чата не может указать на чужой файл.
- **База знаний** читается на каждом запросе (файлы маленькие): правки в `docs/assistant-knowledge` работают без перезапуска.
- **Пробники интерфейса не трогают платные запуски:** при заданном ключе запуск на сервер не передаётся.
